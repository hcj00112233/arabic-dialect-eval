摘要

针对主流模型在阿语方言生成与语体区分上仍显薄弱、标准语与各国方言难以稳定切换的问题[1]，独立设计 154 条结构化评测集与"机器初筛 + 人工深评"双层评审管线，完成 DeepSeek-V3.2、Kimi K3、GPT-6 Astra 三方全量横评：机器初筛 100% 覆盖、评审人力压减 57%，采纳率/幻觉率等指标量化到产品口径，以定位主流模型共同系统性短板，并产出按"提示词 / RAG / 微调"分路线、带代价评估的数据迭代方案。

本评测面向主流 LLM 的阿语能力盲区设计：MSA / 沙特方言 / 埃及方言三语体平行框架，覆盖 7 类任务 × 6 个评分维度 × 10 类归因标签，共 154 条结构化 case。三个模型（DeepSeek-V3.2 / Kimi K3 / GPT-6 Astra）在同一 case 集、同一 rubric、同一 judge（deepseek-chat）下完成实测：各 154 条全量回答 + judge 全量初筛 + 人工层判定（DS / Kimi / Astra 分别为 67 / 67 / 72 条，三侧均已定稿）。

核心发现

三方表现：Astra 在本轮人工层样本中采纳率最高，DeepSeek 次之，Kimi 的优势集中在部分文化与表达任务。GPT-6 Astra 采纳率 97.2%（70/72）、硬伤率 2.8%（2/72）；DeepSeek-V3.2 为 94.0%（63/67）、6.0%（4/67）；Kimi K3 为 89.6%（60/67）、9.0%（6/67）。三方 judge 全量总均分分别为 2.892 / 2.919 / 2.896，处于相近区间。人工层包含人工判定与 AI 代审，样本数量及人工判定占比不同，上述排序仅描述本轮样本表现。Kimi 在部分同题人工评语中获“细节更丰富 / 文采更好”的评价；Astra 虽整体采纳率较高，仍在 S-T2-02 漏掉略带讽刺的语用层次。

共性与差异：语体错配、敬语细节是三家共同短板，Arabizi 数字歧义不能再笼统归为三家共同问题。S-T3-05 的正式演讲→方言推文改写中，三个模型均未彻底摆脱标准语程式化表达；沙特官方敬语缺少 الملكي（A4）也在三家同题出现。E-T7-04 中，DeepSeek 与 Kimi 均把 9 误读为 ق，Astra 则是本轮三家中唯一零样本正确解码 9=ص 的模型；这一单题结果不外推为全部 Arabizi 能力。易混史实幻觉在 DS/Kimi 中均有案例，Kimi 另出现波斯字母 گ 渗入（2/154，DS 为 0）。

评审可靠性：三方结果都需要结合人工复核解读。DeepSeek 同源 judge 存在漏检；Kimi 与 Astra 均出现幻觉式扣分。Astra 的 S-T6-06 正确算术答案被判 D3/D5=0、S-T2-07 海湾通用表达被误判为埃及方言，两例已由人工复核推翻（详见 3.1）。另在 Kimi K3 的 3 条推理样本中，思维链拉丁字符占比为 76%–100%（详见 3.3）；这提示输出语体与推理过程语言可能分离，但字符占比不等同于英语推理比例。

[1] 问题依据：PALM（2025），§5.1 / 表 2发现，其受测模型面对方言阿语指令时，约 90% 的回答仍使用现代标准阿语（MSA）；表中 GPT-4o 与 Claude-3.5-Sonnet 的方言一致性分别为 8.33% 和 9.44%。该数据支持“方言输出与语体跟随仍有短板”，不直接证明模型无法理解方言，也不是本报告三款模型的实测值。

一、评测设计

1.1 三语体框架

阿语是语体连续体，模型必须在三种语体间准确切换：

语体锚点典型场景数据现状
MSA当代规范书面语新闻、公文、正式演讲语料充足
沙特方言利雅得 / Najdi社媒、日常交流、客服海湾语料中占主导；人均 GDP 约为埃及 10 倍，付费用户潜力高
埃及方言开罗社媒、日常交流、客服、影视方言中语料最多

覆盖边界声明：海湾内部细分（科威特/阿联酋/卡塔尔）与马格里布方言不在本期范围内；马格里布 Arabizi 底层为法语正字法，是独立体系。

1.2 评分维度（0-3 分）与归因体系

D1 语体准确性 · D2 语域切换 · D3 知识准确性 · D4 文化适切性 · D5 推理质量 · D6 表达水准（母语者盲评标准）

归因十分类：A1 方言区混用 / A2 语体错配 / A3 翻译腔 / A4 敬语层级错误 / A5 文化幻觉 / A6 推理语言切换 / A7 事实错误 / A8 MSA 规范性错误 / A9 混排-呈现错误 / A10 Arabizi 解析失败

归因标签同时对应问题定位框架：数据层（A5 文化幻觉 / A7 事实错误）、模型层（A1 / A2 / A6 / A3）、提示词层（指令遵循偏差，如一条推文输出四条）、呈现/工程层（A9 / A10）——每条 bad case 先定位出在哪一层，再决定修复路线（补数据 / 调提示词 / 挂核查层 / 改解码），这与线上问题排查是同一套动作。

1.3 Case 集构成（154 条）

T1 生成 30 · T2 理解 24 · T3 语域切换 20 · T4 文化适切 20 · T5 知识 20 · T6 推理 24 · T7 工程呈现层 16。难度 easy:medium:hard ≈ 4:4:2；case 标注来源（expert / draft），标注为 expert 的题目来自一线真实场景。三个模型跑完全相同的 154 条，回答逐条存档。

1.4 方法亮点：T7 工程呈现层

主流评测集系统缺失的盲区：RTL 双向渲染下数字/英文/标点的顺序错乱、东阿拉伯数字（٠١٢٣）与西阿拉伯数字（0123）的国家惯例分裂（埃及用前者、海湾用后者）、tashkeel 发音符号、Arabizi（拉丁化阿语，映射规则绑定方言发音——埃及 ق→2、海湾 غ→8，拼写自带方言区指纹）。

1.6 与现有评测基准的对标与选型判断

动手设计前，我系统调研了 2024 年以来阿语评测方向的主要公开工作，并逐篇核对了一手论文原文（共 8 篇，arXiv PDF 已存档）。结论先行：现有基准无法直接满足"定位生成式方言短板、反哺产品迭代"的目标——它们要么是理解型选择题，要么是文化知识问答，没有一家把真实场景生成、语域切换和工程呈现层放在一起测。但每篇工作都给了我有实证依据的设计输入，下表是"证据 → 判断 → 动作"的完整链路：

论文证据（已核对原文）我的判断落到本评测的动作
Jawaher（UBC/MBZUAI 2025）实测：引入 GPT-4o 做 judge 后，人机一致性 Krippendorff's α 从 0.957 崩到 0.195，作者被迫弃用 judge 分数 阿语方言场景下裸 LLM-as-judge 不可信，这已有学术实证，不是直觉 采用"judge 初筛 + 双层人工评审"架构，并量化 judge 漏检率（DS 侧 4/58）与幻觉式扣分，而非直接采信 judge 分数
PALM（UBC/MBZUAI 2025，17,411 条人工指令对覆盖 22 国）观测：约 90% 方言指令被模型回以 MSA 方言"理解 → 生成"的退化是主战场，但 PALM 只把它当附带观测，未设为计分维度 把语体准确性（D1）与语域切换（D2）设为独立计分维度，T3 类 20 条 case 专测 MSA↔方言双向改写
Dialectal Arabic MMLU（IBM/NYUAD/MBZUAI 2025，5 方言 15,675 题）结论：prompt 中显式标注方言名称反而使模型降分 模型对"显式元指令"和"隐式语体能力"是两回事，真实用户不会说"请用 Najdi 方言" 82% case（126/154）采用场景隐含语体——提问本身写在目标方言里或场景自然决定语体（如沙特方言提问"واحد قال لي «تو الناس»، شنو يقصد؟"），考察模型的语体跟随能力；仅 18%（28 条）含显式语体指令，其中 20 条集中在 T1/T3 改写题，任务性质决定必须指明目标语体
Absher（沙特 KKU 等 2025，18,564 题）：GPT-4o 自动生成题目 + 仅 10% 人工抽检 合成题扩量快，但质量天花板低，考不出区分度——测不出模型真正的"陷阱点" 154 条 case 全部人工原创，每条带 Gold 标准 + 预设陷阱（如 الأزهر 建校年份易混点、分钟减法陷阱）
AraDiCE（QCRI 2024，约 45K 样本）：英文→MSA→方言机器翻译 + 人工后编辑；TII 评测综述（2025，覆盖 40+ 基准）点名此类翻译路径存在文化错位与循环评估风险 经英文中转的数据会系统性丢失文化语境，且可能污染被测模型的训练分布 case 从真实使用场景直接原创，不经过任何语言中转；评测集与公开训练语料零交集（见 3.4 污染声明）

对标矩阵：本评测的增量在哪。

上述工作均发表于 2026 年之前，反映的是上一代模型的能力水位；本评测以 GPT-6 Astra 发布（2026.09）后的新一轮模型能力迭代为时间基准，测试并记录当前主流模型的阿语综合能力。在这一基准上，本评测覆盖了四项上述工作均未涉及的维度：真实产品场景、语域切换显式计分、工程呈现层、干预实验。

基于上述对标，给业务侧的阿语评测体系四步方案：

  1. 许可审计先行：AraDiCE 为 CC-BY-NC-SA（不可进入商用训练管线），Dialectal-MMLU 为 CC-BY 可用，PALM / Jawaher 已在 HuggingFace 公开可获取——数据引入前完成许可审计，这是数据合规的基本功；
  2. 冷启动建基线：以 PALM 的 17,411 条人工指令对套用自有 rubric 复评，零数据生产成本，一周内可建立能力基线；
  3. 迭代期自建场景化评测集：本评测的 154 条即 v1——覆盖真实产品场景、语域切换、工程呈现层，配套"judge 初筛 + 人工复核"双层管线，结论可直接归因到产品迭代；
  4. 公开口径对标：用 PALM / Dialectal-MMLU 等开源基准作对外口径，与内部场景化评测集分开维护，避免评测集污染。

E-T3-02 三方均有缺口 埃及工程师面试沙特公司 人工出题

三家都主动援引了 Vision 2030——它已是此类题目的通用话术，不构成区分度，真正的差距在执行质量：DS 方言体面、规避"为钱"红线执行完整，但亮点止于话术层；Kimi 同题被判"不同意，整体还是比较空泛"；Astra 判【基本同意】，但人工复核指出"内容全围绕自我成长，未体现对沙特社会/市场机遇的针对性"。该题三家均未完全达标——方言地道之外，针对对方市场的具体洞察才是分水岭。

复核稿原文定位：E-T3-02（DS · Kimi · Astra）

S-T2-02 三方同题全踩坑 · 错法各异 تو الناس 词义理解

同一道题三种错法，正好构成三家的短板画像：DS 用生造表达 للتو（人工复核："不知道哪里来的，本地人很少用"）——语料边界问题；Kimi 另混入波斯字母 أگدر（"本地人看到会以为你是波斯人"）——生成纯净度问题；Astra 词义解释正确，但人工复核判"没有表达出略微讽刺的那一层意思"——语用层次问题。

复核稿原文定位：S-T2-02（DS · Kimi · Astra）

S-T3-05 / E-T7-04 / M-T2-03 同题反转 单题胜负互有来回

人工层同集对照发现：S-T3-05（演讲→方言推文）三家同题同型失守，都"基本照录官方原句"（Astra 同判 A2，方言化不彻底）；E-T7-04（Arabizi 解码）DS/Kimi 都把 9 误读为 ق（埃及约定 9=ص），Astra 是唯一零样本正确解码的模型（9=ص、3=ع、7=ح 全对，人工复核仅指出题用词偏罕见）；而 M-T2-03 诗歌背景题 DS 与 Astra 答对（归属 المتنبي 准确、未杜撰），Kimi 反而虚构背景（A7）——单题层面没有常胜方，差距在分布密度。

复核稿原文定位：S-T3-05（DS · Kimi · Astra） · E-T7-04（DS · Kimi · Astra） · M-T2-03（DS · Kimi · Astra）

2.3 各自亮点 Case

DeepSeek 已确认的强项

  • S-T6-01 沙特方言多步推理零退化，主动使用东阿拉伯数字符合海湾惯例；

2.6 人工判定 vs Judge 一致性（双模型交叉验证）

DS 侧已确认 judge 的三类系统性盲区：语感频率判断（الله يعافيك vs يعطيك العافية 哪个更常用）、语义-语用错位（معلش 的安慰 vs 道歉功能）、地域特异性（泛阿拉伯 vs 方言特有）。本轮双侧全量对照又补两类实证：

  • 同源偏宽：judge 给 DS 全量 154 条几乎找不到归因（A1×1、A5×2），人工层却抓到 A7（M-T5-02）、A5（E-T7-02）、A10（E-T7-04 的 9=ق 误读，judge 给全 3 并复述了同样的错误）；judge 对 DS 的 A7 判定在两次运行间不一致（早期小样本初筛标 ×7、全量重跑标 ×0），幻觉判定本身随运行漂移；
  • 幻觉式扣分（Kimi 侧）：M-T6-06 答案 162 完全正确却被 judge 给 D3/D5=0（理由自相矛盾）；S-T6-05 被误称"埃及方言"扣分；S-T2-01 被误判低分——均被人工层推翻。

结论：judge 可承担"语法/事实/结构"层初筛，但"地道性/语用/地域"三层必须人工兜底；judge 与被测模型同源时会系统性偏宽，对不同源模型又会产生幻觉式扣分——bad case 清单必须人工复核后才能进报告，两个方向都验证过。

2.8 评测工程化与成本账

机器层成本（token 账）

  • 被测回答：154 条 × 2 模型，单条 input 约 0.1-0.3K tokens、output 0.5-2K tokens（K3 含思维链），合计约百万 tokens 以内；DeepSeek 按量计费为元级，Kimi 走订阅额度；
  • judge 初筛：154 条 ×（rubric 约 2K + 回答）tokens，deepseek-chat 计费约 ¥2 量级；
  • 结论：机器层全量跑一遍的边际成本不足一杯咖啡，评测的真瓶颈从来不是 token 单价，而是人工复核时间。

人力账（降本手段的实战）

  • 纯人工：154 条 × 约 2 分钟 ≈ 5 小时；双层管线：judge 全量初筛 + 人工只深评核心 64 条 + judge 标记 3 条 ≈ 2.2 小时，人力压减 57%；
  • 这正是"给简单任务换小模型"的评测版：2.6 节证明 judge 在语法/事实/结构层可靠，人工复核时间只投向"地道性/语用/地域"三个机器盲区——把人用在机器替代不了的地方；
  • 进一步降本空间：压缩 judge 的系统提示词（rubric 精简版）、对同任务类型开缓存、初筛换更小的模型，均已列入下一轮迭代。

工程化沉淀

  • runner / judge / 复核稿生成全部脚本化（run_eval_kimi_local.py · judge_kimi3.py · gen_review.py），换新模型重跑一次全量横评 < 10 分钟；
  • token 自动刷新、并发控制、错误重试、结果按 case 顺序落盘（JSONL），复核稿自动生成带【待填】占位——整条管线可复用于任意第三模型。

3.1 Judge 校准：self-preference bias 实测

评审管线使用 LLM-as-judge（deepseek-chat）做初筛，其可信度必须被测量而非假设。用同一 judge 对双模型全量 154 条打分、并与人工层 67 条逐案对照，得到：

指标judge 评 DeepSeek（同源）judge 评 Kimi K3（第三方）judge 评 Astra（第三方）
全量总均分（6 维 × 154 条）2.9192.8962.892
归因标签条数（发现问题数）3 / 1547 / 1544 / 154
漏检率（人工层判 ≤1 分但 judge 全 ≥2）4 / 583 / 542 / 72

judge-人工维度分平均绝对差0.1180.1760.088

解读：judge 对同源模型"更宽容、更少归因、与人工层更一致"，对第三方模型"更苛刻、且会产生幻觉式扣分"——self-preference bias 不是理论风险而是实测存在（尽管总分差仅 0.02，但归因密度差 2.3 倍）。Astra 侧进一步实证：judge 在第三方模型上同样产生幻觉式扣分——S-T6-06 中 Astra 答案 ٤٥-٧+١٢=٥٠ 完全正确，judge 却判"算术自相矛盾"给 D3/D5=0（其理由里自己算出的也是 50）；S-T2-07 中 judge 把海湾通用表达 على عيني وراسي 误判为"埃及方言"，被人工复核当场推翻。两条均为人工实锤。因此本报告所有关键结论均以人工层为准，judge 仅承担初筛。结论升级为："judge 不可裸信"是跨模型普适现象，不因同源/异源而消失；judge 与被测模型应异源，且最好多家 judge 交叉。

3.3 CoT 语言切换观测：thinking 模型带来的新评测维度

K3 为 thinking 模型，API 返回思维链（reasoning_content）——这让 A6「推理语言切换」从"推测"变成"可直接观测的指标"。对 3 条 T6 推理 case 的实测：

Case回答语体思维链语言构成思维链开头
M-T6-01MSA拉丁字符 100% / 阿语 0%"Let me solve this problem step by step in Arabic."
S-T6-03沙特方言拉丁 89% / 阿语 11%"The user says … = 4 people. Total 240 riyals…"
E-T6-03埃及方言拉丁 76% / 阿语 24%"Round trip = 2 rides/day × 12 = 24 جنيه/يوم…"

发现：输出层的地道方言 ≠ 推理层的方言推理。K3 实际工作模式是"用英语思考，用目标语体翻译输出"。这有两层含义：① 两模型 D5 推理同为最低维度，机制可能在此——方言场景的推理经由英语中转，引入语义损耗；② 方言推理能力的真瓶颈在 reasoning 层语料而非 output 层，传统 output 评测看不到这一层，CoT 监测应成为 thinking 模型时代方言评测的标配维度（例如直接测"用沙特方言思考时 D5 是否优于英语中转"——这本身就是下一步的实验设计）。

四、对模型迭代的数据建议（分路线 · 带代价评估）

每条建议标注修复路线与代价——同一个"能力不足"，走提示词、RAG 还是微调，成本和效果上限完全不同：

  1. 方言语料中的"套话程序"标注｜路线：数据层 + SFT 微调。海湾邀请/拒绝/道歉场景的完整客套链条（如邀请必须含宗教客套层 تشرفنا / الله يحييك），现有语料只有"正确的句子"，缺"完整的程序"。代价：需方言母语标注员，周期以月计；高频场景可先用提示词层兜，但干预实验（3.2）已实证：提示词能修格式语气、修不动语体惯性，SFT 不可替代。
  2. Arabizi 语料的系统化构建｜路线：数据层 + 微调（映射规则需内化进权重，本轮确认是双模型共同系统短板）。代价：按方言区分别构建（埃及 2=ق / 海湾 8=غ / 马格里布法语体系），数字歧义 case 需专项覆盖；短期可用提示词注入映射表（RAG 式外挂）——干预实验（3.2）已在 E-T7-04 上完全修复，但方言区指纹分析这类推理仍依赖内化。
  3. "地域特异性"负样本｜路线：偏好优化（DPO 正负例对）。泛阿拉伯表达冒充方言特色的 bad case 集合（如 يا أستاذ 冒充埃及特色），训练模型识别"语料边界"。代价：需人工构造正负例，但量级要求低（百级即可见效），是五条中投入产出比最高的一条。
  4. 易混史实对抗集｜路线：RAG / 事实核查层优先，微调殿后。王朝年代、机构创立、诗歌背景、教法归属属"知识更新频繁、长尾无限"的典型 RAG 适用域——改模型权重存知识既不经济也追不上更新；只有稳定高频事实才值得进微调。代价：知识库建设与持续维护；两模型同病（DS M-T5-02 教法归属错误 / Kimi M-T2-03 虚构诗歌背景），对抗集一次构建双端复用。
  5. 跨语种字母污染清洗｜路线：纯工程手段（语料清洗 + 解码层校验），不动模型。Kimi 回答混入波斯字母 گ（أگدر），提示阿拉伯语生成需防范波斯语/乌尔都语等阿拉伯字母体系语言的字符渗入。代价：五条中最低——生成端加字符集白名单校验（阿语 Unicode 块 + 少量扩展），正则即可拦截。

五、方法论说明与局限

诚实条款：

  • 两侧人工层规模对称（各 67 条）但人工判定占比不同：DS 人工 9 + AI 代审 58，Kimi 人工 13 + AI 代审 54，Astra 人工 13 + AI 代审 59。三侧代审条目均未经人工逐条复核（时间约束），逐条存档于 ds_verdicts.json / kimi3_verdicts.json / gpt6astra_verdicts.json 并与人工判定分开标注，可按需抽检；DS 另有 11 条早期人工判定信号，其中 2 条（S-T1-01/S-T1-02）在 67 集之外，未计入采纳率；
  • 生成参数不完全对齐：Kimi K3 接口强制 temperature=1，DeepSeek 侧为 0.3——温度直接影响输出多样性与创意类任务（T1）的发散度，对比解读时已计入此变量；
  • 成本数字（2.8 节）为按公开定价与实测 token 量的工程估算，用于说明量级而非精确对账；
  • 干预实验（3.2 节）每条路线仅验证 1 条代表 case，结论方向可信但覆盖率有限，不作为路线效果的完整度量；
  • 复核中发现 Gold 标准两处疑似笔误（M-T6-01 参考答案 10:32 应为 10:16；S-T7-04 的 9=ص 与其自身解码矛盾），已在 case 元数据层标注，不影响横评结论；
  • 评测人对海湾内部细分、马格里布方言、逊尼派法学细节主动声明不判定（宁缺毋滥原则）；
  • T5 中"沙特建国日（1727）"为 2022 年新设纪念日，对知识截止较早的模型存在时间不公平，已在 case 元数据中标注。
延伸观察：方言语音数据的 ASR 层失真。评测过程中对一条埃及方言口语视频做 ASR 转写（faster-whisper small），识别结果系统性失真（如将方言词误识别为不存在的 الدتاءة / ممسس）。这提示：方言语音类数据的第一道坎不在模型而在 ASR 层——通用 ASR 对方言口语的转写错误会直接污染下游训练/评测数据，小语种语音数据管线需内置方言适配或人工抽检环节。
